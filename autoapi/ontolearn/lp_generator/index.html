class ontolearn.lp_generator.ComplexityProfile[source]

A named point (or curriculum step) in the space of “how complex should the target be”.

Parameters:

  • name – identifier used to tag generated problems and group benchmark results.

  • allowed_constructs – DL constructors GoalDirectedLPGenerator.generate() may use when sampling a target concept. Relation-based constructs (∃/∀/cardinality/has-value) are silently unavailable on a knowledge base exposing no object properties.

  • min_length/max_length – bounds on concept_len of the (NNF) target.

  • min_depth/max_depth – bounds on restriction-nesting depth (see GoalDirectedLPGenerator.concept_depth()); a bare named class has depth 0.

  • max_arity – maximum number of operands sampled under one intersection/union.

  • card_limit – cardinality restrictions sample n uniformly from [1, card_limit].

  • use_inverse_roles – if True, restrictions may use r- in place of r.

  • min_pos/min_neg – an LP is discarded unless the target has at least this many positive and negative instances in the knowledge base.

  • max_examples_per_side – positives/negatives are subsampled down to this cap.

  • max_baseline_f1 – an LP is discarded if the best of a pool of “cheap” one-step hypotheses (an atomic class, its negation, or a bare exists r.Top) already reaches this F1 – i.e. it is trivially solvable without the constructs being tested.

  • min_difficulty – an LP is discarded if its DifficultyWeights-weighted score falls below this bar. 0.0 (default) disables this filter.

  • oversample_factor – GoalDirectedLPGenerator.generate() collects up to num_lps * oversample_factor passing candidates (subject to max_attempts) before ranking by difficulty and keeping the hardest num_lps – i.e. it actively searches for hard problems instead of returning the first ones found.

  • hard_negative_ratio – fraction of the sampled negatives drawn from the near-miss pool (when one exists) rather than arbitrary non-instances.

  • difficulty_weights – see DifficultyWeights.

class ontolearn.lp_generator.GoalDirectedLPGenerator(knowledge_base: KnowledgeBase, seed: int | None = None, probe_cap: int = 300)[source]

Samples target concepts from an explicit DL-construct grammar and turns them into LPs.

Usage:

kb = KnowledgeBase(path="KGs/Family/family-benchmark_rich_background.owl")
gen = GoalDirectedLPGenerator(kb, seed=1)
profile = ComplexityProfile(
    name="nested-existential",
    allowed_constructs=frozenset({DLConstruct.EXISTENTIAL, DLConstruct.INTERSECTION}),
    max_length=8, max_depth=3,
)
lps = gen.generate(profile, num_lps=10)
model = TDL(kb).fit(lps[0].to_lp())

baseline_f1(pos: Individuals, neg: Individuals) → float[source]

near_miss_negatives(target: owlapy.class_expression.OWLClassExpression, pos: Individuals) → Individuals[source]

Individuals satisfying target with exactly one top-level conjunct dropped, minus pos.

E.g. for C = Compound ⊓ (∃ hasChild.Father) these are individuals that are a Compound but whose child (if any) isn’t a Father, or that have a Father child but aren’t a Compound – the negatives one ablated conjunct away from being positive, which is exactly what trips up a greedy top-down learner.
